# P1 workflow changes — 2026-10-13

The customer audit identified hidden recognition, loss of corrections after image edits, limited document management, and unqualified performance on 4 GB phones. This batch implements the workflow changes. Physical-phone qualification remains outstanding.

## Behavior

- The page editor has a persistent **Recognize text / Recognize again** action in both tabs. The document review has a visible batch action for selected unread pages. Batch recognition and text exports skip pages already recognized, preserving corrections.
- Re-recognition or an image transformation on a recognized page requires confirmation. A successful replacement retains one previous image/text version, including image dimensions, OCR boxes, original readings and confirmed corrections. **Restore previous text** restores the image and text together. The version survives draft save/reload and is consumed on restoration. This is one recovery version, not unlimited undo history.
- Cancelling recognition leaves the current page unchanged, including its recovery version. Processing shows reading, orientation checks and digit checks; batch progress includes the page number. Cancellation waits for the current native step. Completed batch pages remain saved. Failed editor saves restore the previous in-memory state and display an error.
- Files searches document titles, folder names and current recognized/corrected text, including Unicode. Search survives navigation between Home and Files. Folder chips filter results; documents can move to a new/existing folder or Unfiled.
- Document deletion requires explicit confirmation. It removes only that document's app-private directory, including its originals, working copies and exports. Imported external originals and previously shared files remain. Deletion is permanent. Writes and deletion are serialized so a queued save cannot recreate a deleted draft.
- Existing drafts load without a migration. New folder and recovery fields are optional for old JSON. The Files heading fits narrow screens; the editor actions respect the system safe area.

## Remaining P1 acceptance

An actual 4 GB Android phone is required to measure camera/import/OCR/export time, peak memory, storage growth, battery/thermal behavior and background/process interruption with realistic books. The current emulator is API 35 x86_64 with about 2.42 GiB RAM; its timings cannot qualify a phone. Orientation/digit-check defaults remain unchanged pending those measurements. Long-running background work is not guaranteed; keep the app open. Completed batch pages persist, but automatic job resumption and a foreground service are not implemented.

Deleting a document now reclaims its private files. Automatic pruning within a retained document, storage accounting, and permanent single-page deletion are separate work; retained working images may still grow with repeated editing. Recovery intentionally keeps the referenced previous image. Camera field accuracy, real share delivery and production signing remain outstanding.
